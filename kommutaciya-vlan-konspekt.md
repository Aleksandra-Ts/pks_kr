# Коммутация Ethernet и VLAN: краткий конспект

## Тема 1. Технологии коммутации и Ethernet

**Коммутация** — передача данных в локальной сети по **MAC-адресам** (канальный уровень). В отличие от маршрутизатора, коммутатор обычно не меняет IP-адреса, а пересылает **кадры** (frames) между портами.

**Семейство Ethernet** — самая распространённая технология ЛВС. Различают скорости (10/100/1000 Мбит/с, 10 Гбит/с и выше), типы кабеля и разъёмы (витая пара, оптоволокно), режимы **полудуплекс** и **дуплекс**. Современные сети почти всегда работают в **полном дуплексе** на коммутируемых портах.

**Таблица коммутации (MAC-таблица)** — база «MAC-адрес → порт». Коммутатор **учится** сам: когда приходит кадр, записывается адрес отправителя и порт, с которого он пришёл. Если адрес назначения уже есть в таблице — кадр отправляют **только на нужный порт** (unicast). Если записи нет — временно **рассылают на все порты**, кроме входного (**flooding**), пока не появится запись. Широковещательные кадры (broadcast) и неизвестные адреса всегда идут на несколько портов.

**Принятие решения по кадру:**
1. Принять кадр на порт, проверить CRC.
2. Обновить MAC-таблицу по адресу отправителя.
3. Посмотреть адрес назначения: unicast — один порт; broadcast/multicast — группа портов; неизвестный unicast — flooding.
4. При необходимости применить правила VLAN и QoS.

Старый **концентратор (hub)** — общая среда, коллизии; **коммутатор** — отдельный домен коллизий на каждый порт, выше производительность.

## Тема 2. Технология VLAN

**VLAN (Virtual LAN)** — логическое разделение одного коммутатора на несколько **изолированных** сегменты сети. Устройства в разных VLAN не обмениваются кадрами на 2-м уровне, как будто они в разных физических сетях. Это упрощает администрирование, безопасность и снижает широковещательный трафик.

**Порты** бывают:
- **access** — для конечных устройств, один VLAN, кадры **без тега**;
- **trunk** — между коммутаторами (или с роутером), передают кадры **нескольких VLAN**.

**Тегирование кадров** — в заголовок добавляют метку VLAN, чтобы по одному кабелю передать трафик разных сетей.

**Стандарт IEEE 802.1Q** — общий формат тега: 4 байта (в том числе **VID** — номер VLAN, 12 бит, обычно 1–4094). Тег вставляется в кадр Ethernet; на access-порту тег снимают.

**Native VLAN** — VLAN на trunk, для которого кадры **идут без тега** (по умолчанию часто VLAN 1). На обоих концах trunk Native VLAN должен **совпадать**, иначе возможны петли и утечки трафика между VLAN.

**База VLAN на коммутаторе** — список VLAN (номер, имя, какие порты access/trunk). На Cisco: режим VTP (устаревающий) или **ручное** создание VLAN на каждом коммутаторе; важно, чтобы VLAN существовали везде, где нужны.

## Тема 3. Петли в Ethernet и STP

Если коммутаторы соединены **кольцом** или есть **дублирующие** пути, кадры могут ходить по кругу бесконечно — **широковещательный шторм**, переполнение MAC-таблиц, отказ сети.

**STP (Spanning Tree Protocol), IEEE 802.1D** — логически **блокирует** лишние порты, оставляя одно дерево без петель. Выбирают:
- **корневой мост (root bridge)** — с минимальным Bridge ID;
- на каждом сегменте — **назначенный порт (designated)**;
- у остальных — **корневой порт** к root; остальное в **blocking**.

При обрыве связи STP **пересчитывает** дерево (30+ секунд у классического STP).

Развитие семейства:
- **RSTP (802.1w)** — быстрее сходимость;
- **MSTP (802.1s)** — несколько деревьев для разных VLAN;
- **PVST+/RPVST+** (Cisco) — отдельное дерево на VLAN.

STP нужен там, где есть **резервные** или параллельные линии между коммутаторами.

## Тема 4. Маршрутизация между VLAN

Устройства в **разных VLAN** имеют разные подсети IP. Чтобы они общались, нужен **маршрутизатор (L3)**.

**Схема «Router-on-a-stick»** — один физический кабель от роутера к коммутатору, на роутере **подинтерфейсы** (subinterfaces), на коммутаторе — **trunk 802.1Q**. Роутер принимает кадр с тегом VLAN, маршрутизирует между подсетями и отправляет обратно с нужным тегом. Плюс: дёшево, один порт. Минус: **узкое место** по скорости одного канала.

**Многоуровневый коммутатор (Layer 3 switch)** — умеет **маршрутизировать между VLAN** на аппаратном уровне (SVI — виртуальные интерфейсы VLAN). Трафик между VLAN внутри здания не выходит на внешний роутер — быстрее и проще для крупных сетей.

Итог: VLAN делит сеть на 2-м уровне; **маршрутизация между VLAN** — задача 3-го уровня (роутер или L3-коммутатор).

## Тема 5. Агрегация линий связи

**Агрегация (EtherChannel / port-channel)** — несколько физических линков объединяют в **одну логическую** с большей пропускной способностью и **отказоустойчивостью**: при обрыве одного кабеля канал продолжает работать.

Протоколы согласования:
- **LACP (802.1ax)** — открытый стандарт, режимы active/passive;
- **PAgP** — проприетарный Cisco (аналогичная идея «связки» портов).

Порты в группе должны иметь **одинаковые** настройки: скорость, дуплекс, VLAN trunk/access, тип агрегации. Обычно кадры одного потока идут по **одному** физическому линку (хеширование), поэтому удвоение скорости видно при **многих** параллельных сессиях.

**Взаимодействие со STP:** агрегированный канал для STP — **одна логическая связь**. Блокируется весь port-channel, а не отдельный линк внутри (если настроено правильно). Важно не создавать петель **вне** агрегата и согласовать STP root с топологией.

## Тема 6. Защита коммутаторов на уровне доступа

На портах к пользователям и Wi‑Fi часты **атаки канального уровня**. Основные меры:

| Угроза | Защита |
|--------|--------|
| Подмена MAC, переполнение таблицы | **Port security** — ограничение числа MAC на порт, sticky MAC, shutdown при нарушении |
| Подключение «чужого» коммутатора | **BPDU Guard** — отключить порт при получении STP BPDU; **Root Guard** — не дать стать корнем |
| Ложные DHCP-серверы | **DHCP Snooping** — доверенные порты только к настоящему серверу |
| Подмена ARP | **Dynamic ARP Inspection (DAI)** — после DHCP Snooping |
| Подмена IP | **IP Source Guard** |
| Широковещательный флуд | **Storm control** — лимит broadcast/multicast/unicast |
| VLAN hopping | Отдельный **Native VLAN**, не использовать VLAN 1 для данных, отключить неиспользуемые порты |

Принцип: порт доступа — **минимум доверия**, только нужные VLAN, отключены неиспользуемые интерфейсы, на trunk — только необходимые VLAN.
