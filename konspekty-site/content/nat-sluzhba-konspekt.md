# Служба NAT. Технология трансляции адресов — краткий конспект

## Зачем нужна трансляция адресов

В Интернете маршрутизируются только **публичные (глобальные) IP-адреса**. Внутри организации и дома обычно используют **частные адреса** (RFC 1918):

- `10.0.0.0` — `10.255.255.255` (маска /8);
- `172.16.0.0` — `172.31.255.255` (/12);
- `192.168.0.0` — `192.168.255.255` (/16).

Таких сетей может быть сколько угодно, они **не маршрутизируются** в глобальном Интернете. Чтобы тысячи компьютеров выходили в Интернет при **нехватке** публичных IPv4, на **границе сети** применяют **NAT (Network Address Translation)** — трансляцию сетевых адресов.

**Служба NAT** — функция **маршрутизатора или файрвола** (иногда L3-коммутатора): при прохождении пакета **подменяются** IP-адреса (и часто порты) в заголовке и ведётся **таблица соответствий**.

---

## Как работает NAT (общий принцип)

1. Внутренний хост `192.168.1.10` отправляет пакет в Интернет (например, на `8.8.8.8`).
2. Пакет приходит на **внутренний интерфейс** шлюза с NAT.
3. Шлюз **меняет адрес источника** на свой публичный (или из пула) и **запоминает** соответствие в таблице NAT.
4. Ответ из Интернета приходит на **внешний** адрес шлюза — по таблице NAT адрес и порт **возвращают** к `192.168.1.10`.
5. Пакет доставляется внутрь LAN.

Без записи в таблице **входящий** пакет с Интернета к частному адресу напрямую не пройдёт — это и есть «скрытие» внутренней структуры.

## Виды NAT

### Static NAT (статическая)

**Один внутренний адрес** постоянно сопоставлен **одному публичному**.

- пример: сервер в DMZ `192.168.10.5` ↔ `203.0.113.10`;
- снаружи виден только публичный адрес;
- нужен для **постоянной публикации** службы.

### Dynamic NAT (динамическая)

Есть **пул публичных** адресов. Внутренний хост при обращении в Интернет получает **свободный** адрес из пула на время сессии. Когда пул занят — новые сессии могут не установиться.

- реже в малых сетях, чем PAT;
- один внутренний хост в момент сессии = один публичный IP.

### PAT / NAPT / NAT overload (перегруженный NAT)

**Много внутренних** хостов выходят через **один** (или несколько) публичных IP. Различают сессии по **номеру порта** источника.

- самый частый вариант в **офисах и домашних роутерах**;
- пример: `192.168.1.10:54321` → `203.0.113.1:10001`;
- `192.168.1.11:49876` → `203.0.113.1:10002`.

Именно PAT позволяет **сотням ПК** работать с одним адресом провайдера.

### Port forwarding (проброс портов)

Разновидность статического NAT: **внешний порт** на шлюзе перенаправляется на **внутренний IP:порт**.

- пример: с Интернета `203.0.113.1:80` → `192.168.1.100:80` (веб-сервер дома);
- без проброса входящие соединения «с улицы» к внутренним хостам по умолчанию **блокируются**.

## Где выполняется NAT

- **Граничный маршрутизатор** организации;
- **Файрвол / UTM** на выходе в Интернет;
- **Домашний роутер** (режим NAT по умолчанию);
- **Оператор связи** (Carrier-Grade NAT, CGNAT) — несколько абонентов за одним публичным IP провайдера.

**Внутри** корпоративной сети между отделами NAT обычно **не нужен** — там достаточно маршрутизации частных сетей. NAT — типично на **границе** «частная сеть ↔ Интернет».

---

## Плюсы и минусы

**Плюсы:**
- экономия **публичных IPv4**;
- **сокрытие** внутренней адресации и топологии;
- дополнительный **барьер** для случайного входящего трафика (stateful NAT «помнит» сессии).

**Минусы:**
- усложняет **входящие** соединения (игры, P2P, серверы) — нужен проброс или статический NAT;
- ломает некоторые протоколы (**FTP, SIP, IPsec**) — нужны **ALG** (Application Layer Gateway) или обход (VPN поверх NAT, NAT-T для IPsec);
- **не шифрует** трафик — это не замена VPN и файрвола;
- при **CGNAT** у провайдера сложнее поднять домашний сервер и некоторые виды удалённого доступа.

## NAT и IPv6

В **IPv6** адресов достаточно, часто каждый хост получает **глобальный** адрес. Классический NAT для выхода в Интернет **не обязателен**. Иногда используют **NPTv6** (трансляция префиксов) в спецсценариях, но типичная корпоративная схема — маршрутизация IPv6 + **файрвол**, без маскировки адресов как в IPv4.

Переходные сети: **dual stack** (IPv4 + IPv6) — NAT может оставаться на IPv4-канале, пока провайдер не даёт полноценный IPv6.

## Связь с другими службами

| Служба | Роль рядом с NAT |
|--------|------------------|
| **DHCP** | выдаёт внутренним хостам частные IP и адрес шлюза (часто тот же роутер с NAT) |
| **DNS** | резолв имён; NAT не меняет логику DNS |
| **Firewall** | фильтрует до/после NAT; правила часто привязаны к **внутренним** или **внешним** зонам |
| **VPN** | туннель может обходить NAT или требовать **NAT Traversal** (UDP 4500) |

**Таблица NAT** на устройстве Cisco смотрят командой `show ip nat translations` — видно активные соответствия внутренних и внешних адресов/портов.

---

## Краткие определения для экзамена

- **Inside local** — реальный адрес хоста в LAN (например, 192.168.1.10).
- **Inside global** — адрес, под которым хост виден снаружи после NAT.
- **Outside global** — публичный адрес узла в Интернете.
- **Outside local** — как адрес внешнего узла виден изнутри (редко, при обратной трансляции).

**Итог:** служба NAT на границе КС позволяет **безопасно и экономно** подключать частные сети к Интернету; в проекте указывают тип NAT, пул адресов, пробросы для серверов и учитывают ограничения для VoIP, VPN и IPsec.
