# Возможные темы контрольной работы (по логике прошлых лет)

**Формат задания (как в примере):**  
*«Принцип работы / настройки [технологии] на примере [инструмент Linux] с примерами команд / конфигурации».*

---

## Уже встречалось (прошлый год)

| № | Тема | Инструмент / пример |
|---|------|---------------------|
| 1 | Межсетевой экран | **nftables** |
| 2 | Прокси-сервер прикладного уровня | **Squid** |
| 3 | Управление пользователями в Linux | команды `useradd`, `usermod`, `groupadd`, `id`, `sudo` |
| 4 | Резервное копирование и архивирование | `tar`, `rsync`, `cron` |
| 5 | Анализ трафика | **tshark** / Wireshark CLI |

## Сети и безопасность (nftables, iptables, фильтрация)

1. Принцип **stateful-фильтрации** на примере правил **nftables** (таблицы `inet filter`, цепочки `input`/`forward`/`output`).
2. Принцип **NAT (маскарадинг)** на примере **nftables** (`nat postrouting`, `masquerade`).
3. Принцип работы **iptables/nftables** для защиты SSH — разрешить порт 22 только с подсети.
4. Принцип **блокировки ICMP** и разрешения установленных соединений (`ct state established,related`).
5. Принцип **port forwarding (DNAT)** на примере **nftables** (проброс 80/tcp на внутренний сервер).
6. Сравнение **iptables и nftables** — базовый синтаксис набора правил.
7. Принцип **зональной модели** (внутренняя/внешняя сеть) на примере двух интерфейсов и `forward` в nftables.

---

## Прокси, DNS, веб-доступ

8. Принцип **кэширующего прокси** на примере **Squid** (`http_port`, `acl`, `http_access`).
9. Принцип **прозрачного прокси** (перехват HTTP) — Squid + перенаправление в nftables.
10. Принцип **аутентификации на прокси** — Squid + `basic_ncsa_auth`, файл `htpasswd`.
11. Принцип работы **DNS-сервера** на примере **BIND9** или **dnsmasq** (зона, A-запись, forwarders).
12. Принцип **разрешения имён** на примере `/etc/hosts` и `systemd-resolved` / `resolvectl`.
13. Принцип **обратного прокси** на примере **nginx** (`proxy_pass` на backend).
14. Принцип **виртуальных хостов** HTTP на примере **nginx** / **Apache**.

---

## Маршрутизация, VLAN, сегментация (Linux как маршрутизатор)

15. Принцип **статической маршрутизации** — `ip route add`, `ip route show`, default gateway.
16. Принцип **включения IP-forwarding** — `sysctl net.ipv4.ip_forward`, постоянная настройка в `sysctl.d`.
17. Принцип **VLAN (802.1Q)** на примере `ip link add link eth0 name eth0.10 type vlan id 10`.
18. Принцип **моста (bridge)** между интерфейсами — `ip link add type bridge`, `brctl`.
19. Принцип **policy routing** — таблицы маршрутизации `ip rule`, `ip route add table`.
20. Принцип **DHCP-сервера** на примере **isc-dhcp-server** или **dnsmasq** (`subnet`, `range`, `option routers`).
21. Принцип **DHCP-клиента** — `dhclient`, NetworkManager.
22. Принцип **сегментации сетевыми namespace** — `ip netns add`, маршрутизация между netns.

---

## VPN и удалённый доступ

23. Принцип **site-to-site VPN** на примере **WireGuard** (`wg`, `wg-quick`, конфиг `[Interface]` / `[Peer]`).
24. Принцип **удалённого доступа** на примере **OpenVPN** (ключи, `tun`, маршруты `push`).
25. Принцип **IPsec** на примере **strongSwan** / `swanctl` (упрощённо: соединение, left/right).
26. Принцип **SSH-туннеля** — локальный и удалённый проброс портов (`ssh -L`, `ssh -R`).

---

## Анализ трафика и диагностика

27. Принцип **захвата пакетов** на примере **tcpdump** (`-i any`, фильтр `host`, `port`).
28. Принцип **анализа протоколов** на примере **tshark** (фильтры `http`, `dns`, `tcp.stream`).
29. Принцип **проверки связности** — `ping`, `traceroute`, `mtr`.
30. Принцип **просмотра сокетов и портов** — `ss -tulpn`, `netstat`.
31. Принцип **ARP и соседей** — `ip neigh`, `arping`.
32. Принцип **мониторинга интерфейсов** — `ip -s link`, `iftop`, `nload`.
33. Принцип **тестирования пропускной способности** — `iperf3` (клиент/сервер).
34. Принцип **DNS-диагностики** — `dig`, `nslookup`, `host`.

---

## Управление пользователями, правами, аудит

35. Принцип **учётных записей** — `useradd`, `userdel`, `passwd`, `/etc/passwd`, `/etc/shadow`.
36. Принцип **групп и прав** — `groupadd`, `usermod -aG`, `chmod`, `chown`, `umask`.
37. Принцип **sudo** — `/etc/sudoers`, `visudo`, `sudo -l`.
38. Принцип **ACL Linux** — `setfacl`, `getfacl` на каталоге общего доступа.
39. Принцип **квот диска** — `quotactl`, `edquota` (если в программе).
40. Принцип **аудита событий** — `auditd`, `ausearch`, `aureport`.
41. Принцип **PAM** (общие политики входа) — файлы в `/etc/pam.d/` (теория + пример `pam_limits`).

---

## Резервное копирование, архивы, восстановление

42. Принцип **полного и инкрементного бэкапа** — `tar -czf`, `tar --listed-incremental`.
43. Принцип **синхронизации каталогов** — `rsync -avz`, `rsync` по SSH.
44. Принцип **снимков** — `rsnapshot`, конфиг `backup_level`, `interval`.
45. Принцип **расписания задач** — `crontab -e`, `/etc/cron.d/`.
46. Принцип **сжатия** — `gzip`, `bzip2`, `xz`, `zstd`.
47. Принцип **проверки целостности архива** — `tar -tzf`, `md5sum`, `sha256sum`.
48. Принцип **резервирования конфигов сети** — копирование `/etc/nftables.conf`, `/etc/squid/`, git.

---

## Службы и автозапуск

49. Принцип **systemd** — `systemctl start/stop/enable/status`, unit-файлы `.service`.
50. Принцип **журналирования** — `journalctl -u squid`, `-f`, `--since`.
51. Принцип **ограничения ресурсов службы** — `MemoryMax`, `CPUQuota` в unit-файле.
52. Принцип **сокетов и таймеров systemd** — `.socket`, `.timer` для бэкапа по расписанию.

---

## По темам курса «Корпоративные сети» (теория + Linux где уместно)

53. Принцип **NAT** — теория + демонстрация `nftables masquerade` / `iptables -t nat`.
54. Принцип **разделения доступа** — VLAN + **nftables** по подсетям.
55. Принцип **DMZ** — три интерфейса, правила `forward` (разрешить 80 только на DMZ).
56. Принцип **сегментирования** — несколько VLAN/subnet + маршрутизация на Linux-шлюзе.
57. Принцип **отказоустойчивости шлюза** — **Keepalived** + VRRP (виртуальный IP).
58. Принцип **агрегации каналов** — **bonding** / `teamd` (`mode=802.3ad`, LACP).
59. Принцип **STP** — на коммутаторе (теория); в Linux — мост без петель, `bridge link`.
60. Принцип **Wi‑Fi точки доступа** — **hostapd** (базовый `ssid`, `wpa_passphrase`) — если в лаборатории.
61. Принцип **RADIUS для 802.1X** — **FreeRADIUS** + теория (упрощённый `clients.conf`, `users`).
62. Принцип **SNMP-мониторинга** — **snmpd**, опрос `snmpwalk` с рабочей станции.
63. Принцип **syslog-сервера** — **rsyslog** remote logging (`@192.168.1.1`).
64. Принцип **NetFlow/sFlow** — сбор потоков (теория + `nfdump` / softflowd — если проходили).

---

## Дополнительно (реже, но встречается на СПО)

65. Принцип **IPv6** — адресация `ip -6 addr`, маршруты `ip -6 route`, ping6.
66. Принцип **TLS/сертификатов** — `openssl req`, проверка HTTPS на nginx.
67. Принцип **fail2ban** — защита SSH от перебора (`jail.local`, `sshd`).
68. Принцип **контейнерной изоляции сети** — Docker bridge, `docker network`.
69. Принцип **файрвола хоста** — **ufw** как фронтенд к nftables (`ufw allow`, `ufw enable`).
70. Принцип **тестирования правил** — `nft -c -f`, `nft list ruleset`, сброс счётчиков.

## Шаблон ответа на контрольную (рекомендация)

Для любой темы из списка удобно структурировать ответ так:

1. **Назначение** технологии в КС (2–4 предложения).
2. **Принцип работы** (уровень OSI, кто с кем взаимодействует).
3. **Схема** (текстом или ASCII): клиент → шлюз → сервер.
4. **Пример конфигурации** (фрагмент файла или команды).
5. **Проверка** — команда диагностики (`ss`, `nft list`, `curl`, `tshark -r`).
6. **Типичные ошибки** (1–2 пункта).
